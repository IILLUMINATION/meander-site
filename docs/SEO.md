# SEO: как квесты попадают в поисковики

Документ для меняющегося состава: что было сломано, как это починено, как
проверить локально и какие решения ещё не приняты.

## 1. Диагноз (измерено 10.10.2026 прямо на проде, до правок)

| Что | Было |
| --- | --- |
| `/market/<uuid>` | 13 074 Б HTML, в `<body>` только «Загрузка квеста...». Текст квеста в HTML отсутствовал |
| `/robots.txt` | 404 |
| `/sitemap.xml` | 404 |
| `/og-image.jpg` | 404 (на него ссылался `layout.tsx`) |
| `canonical` | `https://meander.ru` — мёртвый домен, не этот сайт |
| `metadataBase` | не задан → относительные OG-ссылки нерабочие |
| `<title>` квеста | совпадал с заголовком главной для всех 214 страниц |

Причина общая: все страницы были чисто клиентскими (`useEffect` + axios), а
сервер не отдавал ничего. Робот, который не исполняет JS (а Yandex индексирует
так большую часть), видел пустоту.

## 2. Что сделано

Серверная обёртка + клиентский остров. Клиентские компоненты не переписаны:
данные приходят им пропсами, поэтому React рендерит их на сервере точно так же,
как в браузере. Никакого «текста для робота, пустоты для человека» — это
клоакинг, за него песочат.

| Файл | Роль |
| --- | --- |
| `src/lib/seo.ts` | чтение API с сервера, кэш каталога, `excerpt`, `pluralRu`, `jsonLd` |
| `src/lib/quest.ts` | тип `Quest` (был продублирован в двух страницах) |
| `src/lib/genres.ts` | перевод жанров; обычный модуль, потому что `use client`-файл не может импортировать значения из страницы |
| `src/app/market/page.tsx` | серверная обёртка маркета + его `generateMetadata` |
| `src/app/market/MarketClient.tsx` | прежний клиент, принимает `initialQuests` |
| `src/app/market/[id]/page.tsx` | серверная обёртка квеста, метаданные, JSON-LD |
| `src/app/market/[id]/QuestDetailClient.tsx` | прежний клиент, принимает `initialQuest` |
| `src/app/profile/[id]/page.tsx` | серверная обёртка автора: карточка из `/profiles/<id>`, квесты из кэша каталога, `generateMetadata`, JSON-LD `ProfilePage` |
| `src/app/profile/[id]/ProfileClient.tsx` | прежний клиент (переименован из `page.tsx`), принимает `userId`/`initialProfile`/`initialQuests` |
| `src/lib/profile.ts` | тип `Profile` (был заперт внутри `use client`-файла) |
| `src/app/robots.ts`, `src/app/sitemap.ts` | robots и карта из каталога |
| `src/app/opengraph-image.jpg` | 1200×630, раздаётся по `/opengraph-image.jpg` |
| `src/app/layout.tsx` | `metadataBase` = meander.sbs, canonical-ссылка на мёртвый домен убрана, шаблон заголовков |
| `src/app/docs/[slug]/page.tsx` | серверная страница статьи: SSG-параметры из реестра, `generateMetadata`, canonical, OG-article |
| `src/app/docs/[slug]/DocsArticleClient.tsx` | прежний клиент статьи (переименован из `page.tsx`), markdown теперь приходит пропсом |

После правок (промерено на собранном билде, 5 квестов с самыми длинными
описаниями): 40–43 КБ HTML, 1450–2325 знаков видимого текста, 0 из 40 контрольных
слов описания отсутствуют в HTML у всех пяти. У короче описанного квеста страница
отдаётся 38 КБ и 705 знаков — текст в HTML есть всегда, его объём зависит от
того, сколько написал автор.

`/market` — 472 КБ HTML с карточками, `<title>` и `<description>` по фактическому
содержимому каталога. `/sitemap.xml` — 310 URL (200 квестов + 105 авторов +
главная/маркет/docs).

Страницы авторов (`/profile/<id>`) были четвёртой такой же клиентской страницей:
робот получал 13.8 КБ оболочки с `<title>Meander — текстовые квесты</title>`, без
имени и без списка квестов, хотя ссылка на автора стоит на каждой странице
квеста. Переделаны по той же схеме: сервер тянет карточку `/profiles/<id>` (это
НЕ под `publicQuestLimiter` — лимитер висит только на `/quests*`, `app.ts:194`),
а квесты автора группирует из уже закешенного каталога, то есть лишний запрос к
API на страницу ровно один. После правок: `/profile/3a84a172…` (10 квестов) —
77 КБ, имя, био, счётчики, 10 ссылок на квесты и JSON-LD `ProfilePage` в первом
HTML; `/profile/965502fd…` (1 квест) — 37 КБ. Несуществующий id и битый id — 404.

Статьи документации (`/docs/[slug]`) были такой же клиентской страницей:
`useEffect` + fetch `/docs/<slug>.md`, то есть в HTML лежало 126 знаков
«Загрузка статьи...», а sitemap при этом объявлял эти URL. Переделаны в SSG:
`generateStaticParams` берётся из `docArticles`, markdown читается на билде с
диска (`public/docs/<slug>.md`) и передаётся клиенту пропсом, сетевой fetch
убран совсем. После правок: `/docs/what-is-meander` — 28 996 Б / 1928 знаков
видимого текста, `/docs/quest-structure` — 60 477 Б / 8065 знаков, консоль
браузера чистая (без hydration-ошибок).

Побочное изменение, которое надо принять сознательно: `dynamicParams = false`,
и неизвестный slug отдаёт 404. В `public/docs/` лежит `test-article.md`, которого
нет в реестре, — раньше он открывался по `/docs/test-article`, теперь это 404.
Файл я не трогал; чтобы страница вернулась, статью нужно добавить в
`src/lib/docs-registry.ts`, а не просто положить markdown.

## 3. Ограничение, которое определяет всю архитектуру

Анонимный `/quests*` на бэкенде лимитирован **60 запросами на 15 минут с одного
IP** (`publicQuestLimiter`). Краулер проходит сотни URL за минуты. Поэтому:

1. Каталог читается **одним** запросом и сидит в кэше процесса 5 минут
   (`getQuestList`). Со скольких бы страниц ни перегенеривалась выдача, API
   получает один запрос за TTL.
2. Отзывы (`/quests/:id/reviews`) на сервере **не** рендерятся — они остались
   клиентскими. Это сознательно: их индексация не нужна, а запросов они стоят.
3. Если квеста нет в каталоге (снят с листинга или 18+), страница переспрашивает
   API точечно и отдаёт страницу с `noindex, nofollow` и без canonical. Ссылки
   из Telegram продолжают работать, но в индекс такое не попадает.
4. `apiJson` бросает исключение вместо `[]`. Молча вернуть пустой список
   нельзя: пустая страница уехала бы в ISR-кэш, и краулер получил бы пустой
   маркет вместо внятной ошибки. **Сборка при недоступном бэкенде падает — это
   по дизайну.**

## 4. Гигиена, уже зашитая в код

- `Math.random()` в подборке «Скрытые алмазы» заменён на FNV-1a от `id`:
  случайная на каждый рендер выдача гарантировала hydration mismatch.
- Дата отзыва форматируется с явным `timeZone: "Europe/Moscow"` — сервер в UTC,
  браузер в +3, расхождение тоже ломает гидратацию.
- Фоновая перезагрузка не подменяет отрендеренное сервером спиннером
  (`if (loading && !quest)`), иначе робот видел бы «Загрузка...» на живой странице.
- В JSON-LD `<` экранируется: заголовок и описание пишет пользователь, и
  `</script>` из чужого текста сломал бы страницу.
- Битый или несуществующий id → 404, а не 500. Бэкенд на неверный формат UUID
  отвечает 400 («Invalid ID format»), на валидный несуществующий — 404; оба
  считаются «страницы нет». id дополнительно проверяется регуляркой до запроса,
  чтобы путь из URL не ушёл в адрес API.

## 5. Как проверить локально

```bash
cd /home/user/meander-site
npm install --no-package-lock   # в lockfile 550 URL на npmmirror, npm 12 их блокирует
npm run build
npx next start -p 3010 &
```

Ожидаемое:

```bash
curl -s localhost:3010/robots.txt                 # Sitemap: https://meander.sbs/sitemap.xml
curl -s localhost:3010/sitemap.xml | grep -c '<loc>'   # 310 = главная + маркет + docs + 200 квестов + 105 авторов
page=$(curl -s localhost:3010/market | grep -o 'market/[0-9a-f-]\{36\}' | head -1)
curl -s "localhost:3010/$page" | grep -o '<title>[^<]*\|rel="canonical"\|application/ld+json'
curl -s -o /dev/null -w '%{http_code}\n' "localhost:3010/market/11111111-2222-3333-4444-555555555555"   # 404
profile=$(curl -s localhost:3010/market | grep -o 'profile/[0-9a-f-]\{36\}' | head -1)
curl -s "localhost:3010/$profile" | grep -o '<title>[^<]*\|"@type":\s*"ProfilePage"'   # имя автора в заголовке
curl -s -o /dev/null -w '%{http_code}\n' "localhost:3010/profile/11111111-2222-3333-4444-555555555555"  # 404
curl -s localhost:3010/docs/quest-structure | wc -c            # ~60 КБ, текст статьи в HTML
curl -s -o /dev/null -w '%{http_code}\n' localhost:3010/docs/test-article   # 404: slug не в реестре
```

Нюансы проверки:

- curl без User-Agent бэкенд и Cloudflare режут (403) — для своих запросов
  используйте `node -e` с `https.get` или задавайте UA.
- Hydration: открыть страницу в браузере, консоль должна быть чистой по части
  «Did you render ... on the server and ... the client».
- Проверка для поисковиков: «Диагностика → Проверка URL» в Yandex Webmaster и
  URL Inspection в Google Search Console, оба require подтверждённого владения
  доменом — см. §7.

## 6. Что здесь же, а что нет

В индекс попадают только опубликованные и не 18+ квесты: анонимный `GET /quests`
отдаёт 200 записей из 214 опубликованных (14 отфильтрованы как NSFW). Это
согласуется с `sitemap.ts`: он строится из того же ответа, поэтому «в карту»
невозможно отправить то, что робот и так не увидел бы.

## 7. Открытые решения (нужно его «да»)

1. **Канонический домен.** Сейчас всё записано на `meander.sbs`. Если
   приоритет `meander.ru`, нужны: редирект 301 со второго на первый и правка
   `SITE_ORIGIN` + `metadataBase`. Пока `meander.ru` по-прежнему мёртв, в
   `layout.tsx` canonical на него удалён.
2. **Демо-квесты.** В каталоге 90 записей из 200 помечены `is_demo` — они тоже
   индексируются и лежат в карте. Доля подозрительно большая, стоит проверить,
   все ли они должны светиться в выдаче. Фильтрация делается в одной строке в
   `sitemap.ts` и в `generateMetadata`.
3. **Rich-сниппеты со звёздами.** Не сделаны намеренно: API отдаёт
   `average_rating` без количества оценок, а `aggregateRating` без
   `ratingCount` — это либо выдуманное число, либо невалидный JSON-LD.
   Правка бэкенда — одна строка (`COUNT(*) AS rating_count` рядом с `AVG`),
   но это деплой на прод: ~0.5 дня с проверкой.
4. **Страницы авторов** (`/profile/<id>`) — ~~остались чисто клиентскими~~
   **сделано 10.10.2026**: серверная обёртка, метаданные, JSON-LD, авторы в
   sitemap, ссылка на автора в карточке маркета вместо `<span onClick>`.
5. **Подтверждение владения и подача карты.** Без Yandex Webmaster и Google
   Search Console индексация идёт, но медленно и вслепую. Нужны DNS-записи или
   HTML-файл в `public/` — это прод.
6. **`/api-docs`, `/branding`** — технические страницы, в карте их нет. Если
   они должны находиться, скажите.
7. **Внутренняя перелинковка маркета.** В SSR `/market` попадает 45 ссылок на
   квесты: `displayCount` стартует с 24, остальные — «Показать ещё». Робот
   доходит до них через sitemap, но для веса страниц лучше больше внутренних
   ссылок. Поднять стартовый `displayCount` (например, до 60) — одна строка;
   отдельный «линквалл» изо всех 200 не советую: это пограничный с клоакингом
   приём.
8. **Сколько авторов индексировать.** В карту легли все 105 авторов каталога,
   но 69 из них — авторы одного квеста: их страница почти повторяет страницу
   этого квеста. Если поисковик сочтёт их дублями, фильтр в `sitemap.ts` —
   `.filter(([, qs]) => qs.length >= 2)` (одна строка), плюс такой же `noindex`
   в `generateMetadata` страницы автора, чтобы он не противоречил карте.

## 8. Пайплайн выкатки (тоже требует «да»)

Сборка и деплой делаются на проде, не здесь:

```bash
ssh srv
cd /var/www/meander-site && git pull
pm2 restart meander-site     # порт 3002, наружу через nginx/Cloudflare на meander.sbs
```

Порядок: `git push` в `IILLUMINATION/meander-site` → pull на VPS → `pm2 restart`
→ проверка из §5 уже против боевого адреса. Оба шага с «да».
